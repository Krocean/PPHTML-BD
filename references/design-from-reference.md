# 레퍼런스의 디자인으로 만들기

"이 사이트처럼", "이 PPT 스타일로", "우리 회사 템플릿 느낌으로", "이 design.md 대로" 같은 요청을 받았을 때 읽는다.
레퍼런스에서 **보는 방식(색·글자·모양·배치)** 을 가져와 사용자의 내용에 입힌다. 페이지는 템플릿에 맞추지 않고 내용에 맞게 새로 짠다.

## 목차
1. 얼마나 똑같이 할지 먼저 정한다
2. 레퍼런스에서 스타일 뽑기 (`get-style.ps1`)
3. 뽑은 것을 그림과 맞춰 보고 고친다
4. 그 디자인으로 덱 시작하기
5. 페이지를 자유롭게 쓰는 법
6. `design.md` 를 받았을 때
7. 그대로 가져오기 (같은 CSS, 같은 PPT 틀)
8. 글꼴
9. 가져오지 않는 것
10. 한계와 확인한 범위

## 1. 얼마나 똑같이 할지 먼저 정한다

| 사용자가 원하는 것 | 하는 일 |
|---|---|
| 비슷한 느낌 | 2~5장: 스타일을 뽑아 테마와 `design.md` 로 만들고, 그 약속을 지키며 페이지를 새로 쓴다 (기본) |
| 그대로 (자기 것·자기 회사 것) | 7장: 레퍼런스의 CSS 를 그대로 쓰거나, 레퍼런스 PPT 를 바탕 덱으로 삼는다 |
| 글로 적힌 디자인 규칙을 따라 | 6장: `design.md` 를 읽고 값으로 옮긴다 |

말이 없으면 "비슷한 느낌"으로 한다. 남의 사이트나 남의 덱을 "그대로"는 하지 않는다(9장).

## 2. 레퍼런스에서 스타일 뽑기

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬>\scripts\get-style.ps1" -From "<레퍼런스>" -Out "C:\작업\style-이름" -Name 이름
```

| 레퍼런스 | 어떻게 읽나 | 읽어 내는 것 |
|---|---|---|
| HTML 파일 (여러 장은 `"a.html|b.html"`) | Edge(화면 없음)로 열어 화면의 요소를 잰다 | 바탕·면·글자·강조색, 색이 있는 색들, 글꼴과 크기·굵기·자간, 모서리, 그림자·테두리, 단추와 카드의 생김새, 페이지가 선언한 CSS 변수 |
| 웹 주소 (`https://...`) | 같은 방법. 그 주소를 한 번 불러온다 | 위와 같다. 로그인해야 보이는 화면, 자동 접속을 막는 사이트는 읽지 못한다 |
| PPT (`.pptx .pptm .ppt .potx`) | 숨은 PowerPoint 로 읽기 전용·매크로 끔으로 연다 | 테마 색과 글꼴, 실제 슬라이드의 배경·글자색·채움색, 제목과 본문의 글꼴·크기, 둥근 사각형의 모서리, 그림자 비율, 처음 몇 장의 그림 |
| 그림 (`.png .jpg`) | 색만 센다 | 많이 쓰인 색 열 가지. 글꼴·모서리·배치는 그림을 보고 직접 적는다 |

결과 폴더에 생기는 것:

| 파일 | 내용 |
|---|---|
| `ref_01.png` … | 레퍼런스의 모습 (HTML 은 첫 화면, PPT 는 처음 여섯 장) |
| `theme-이름.css` | 키트의 테마 파일. 잰 값에서 나머지(옅은 색, 선, 눌림, 차트 색, 그림자)를 계산해 채웠다 |
| `preview.png` | 그 테마로 키트의 부품을 한 장에 그린 것 |
| `design.md` | 디자인을 글로 적은 **초안** (색·글자·모양은 채워져 있고, 인상·배치·하지 말 것은 비어 있다) |
| `style.json` | 잰 값 전부(`measured`)와 테마의 바탕값(`base`) |

## 3. 그림과 맞춰 보고 고친다

뽑은 값은 규칙으로 고른 것이라 틀릴 수 있다. **`ref_*.png` 와 `preview.png` 를 나란히 열어 본다(Read).**

볼 것: 바탕과 카드의 밝기 차이가 같은가 · 강조색이 맞는가(가장 눈에 띄는 한 색) · 제목 글꼴의 종류(명조/고딕)와 굵기 · 모서리가 각졌는지 둥근지 · 카드의 경계가 그림자인지 선인지 · 단추가 강조색인지 검정/흰색인지.

다르면 값을 바꿔 테마를 다시 만든다(바꾸고 싶은 것만 적는다. 나머지는 `style.json` 의 값이 쓰인다):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬>\scripts\new-theme.ps1" -From "C:\작업\style-이름\style.json" -Name 이름 -To "C:\작업\style-이름" -Accent "#1F5F4A" -Radius 2 -Shadow border -Button ink
```

| 옵션 | 뜻 |
|---|---|
| `-Bg` `-Surface` `-Ink` `-Accent` | 바탕, 카드 면, 글자, 강조 (`#RRGGBB`) |
| `-Colors "#..,#.."` | 차트에 쓸 다음 색들 |
| `-Display` `-Body` | 제목 글꼴, 본문 글꼴 (`"Inter, Pretendard"`) |
| `-DisplayWeight` `-StrongWeight` | 제목 굵기, 굵은 글자의 굵기 (100~900) |
| `-Tracking` | 제목 자간(em). 촘촘한 큰 제목은 `-0.03` |
| `-Radius` `-ButtonRadius` | 카드 모서리(px), 단추 모서리(px 또는 `pill`) |
| `-Shadow` | `soft` 옅은 그림자 · `lift` 떠 보임 · `border` 가는 테두리 · `none` 면의 색 차이만 |
| `-Button` | 주 단추의 바탕: `accent` 또는 `ink` |
| `-LabelCase` | 작은 머리말: `none` 또는 `uppercase` |

그리고 `design.md` 의 빈 곳을 채운다: **1 한 줄 인상**, **5 배치**(제목이 놓이는 자리와 정렬, 여백, 한 장의 덩어리 수), **7 하지 말 것**.
이 세 가지가 "색만 같은 다른 디자인"과 "같은 디자인"을 가른다. 색과 글꼴은 테마가 지켜 주지만 배치는 페이지를 쓰는 사람이 지킨다.

## 4. 그 디자인으로 덱 시작하기

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<스킬>\scripts\new-deck.ps1" -To "C:\작업\내덱" -Design "C:\작업\style-이름" -Blank 5 -Titles "문제|해법|숫자|일정|요청" -Name "발표 이름"
```

- `design\` 에 `design.md`·레퍼런스 그림·`style.json` 이, `kit\` 에 그 테마가 들어간다. 페이지는 빈 캔버스 다섯 장이다.
- 레퍼런스에 사이트 머리(메뉴)가 없으면 `-NoNav` 를 붙인다(PPT 레퍼런스는 보통 없다).
- 예시 페이지를 섞고 싶으면 `-Pages "blank,kpi,blank"` 처럼 쓴다. 예시 페이지도 같은 테마를 입는다.

## 5. 페이지를 자유롭게 쓰는 법

빈 페이지(`assets/page-blank.html`)는 틀이 아니라 출발점이다: 그냥 웹 페이지이고, 요즘 브라우저에서 되는 것은 쇼 안에서도 된다(`modern-web.md` 를 먼저 읽는다).
레퍼런스의 디자인을 따를 때 지킬 것:

- **보이는 창은 1280 × 720 px.** 한 화면에 맞춰도 되고, 레퍼런스가 길게 읽는 페이지면 길게 써서 슬라이드 안에서 스크롤하게 해도 된다. 한 장(한 화면)에 말할 것 하나.
- **색·글꼴·모서리·그림자는 테마 변수로**: `var(--ph-bg)` `--ph-surface` `--ph-ink` `--ph-ink2` `--ph-line` `--ph-accent` `--ph-display` `--ph-body` `--ph-radius` `--ph-shadow` … (전체 목록: `kit.md` 2장).
  값을 직접 적으면 디자인을 바꿀 때 그 장만 남는다.
- **`design.md` 를 지킨다**: 제목의 크기와 자리, 여백, 카드의 생김새, 강조색을 쓰는 곳. 장을 쓸 때마다 레퍼런스 그림을 다시 본다.
- **레퍼런스가 쓰는 기법을 그대로 쓴다.** 유리 효과, 큰 사진 위의 글, 스크롤에 따라 나타나는 요소, 화면 전환, 움직이는 배경 같은 것이 그 디자인의 일부면 같이 가져온다(값만 맞추고 움직임을 빼면 다른 디자인이 된다). 쓴 그대로 돈다.
- **키트는 도구 상자다.** `ph-card`, `ph-btn`, `PH.bars`, `PH.countUp`, 발표 도구(`PH.deck()`)처럼 필요한 것만 가져다 쓰고, 레퍼런스의 생김새와 다른 부품은 직접 만든다(위 예시 덱의 목록 줄, 결제 방식 단추처럼).
- 눌러 볼 것을 한 장에 하나쯤 둔다: 고르면 숫자가 바뀌는 단추, 줄을 누르면 바뀌는 상세. 이것이 PPT 에 HTML 을 쓰는 이유다.

쓰고 나서: `check-html.ps1 -Html "pages\01-blank.html"` 로 그림을 보고, 레퍼런스 그림 옆에 놓았을 때 같은 집안으로 보이는지 확인한다.

## 6. `design.md` 를 받았을 때

사용자가 디자인 규칙을 글로 준 경우(디자인 도구가 내보낸 `DESIGN.md`, 회사 스타일 가이드, 직접 쓴 메모). 형식은 저마다 다르므로 읽고 뜻으로 옮긴다:

| 문서에 적힌 것 | 옮기는 곳 |
|---|---|
| 배경 / surface / canvas 색 | `-Bg`, `-Surface` |
| 글자 / text / on-surface / foreground | `-Ink` |
| primary / brand / accent | `-Accent` (그 위 글자색은 계산된다) |
| secondary, tertiary, 차트·데이터 색 | `-Colors` |
| 제목(headline, display) 글꼴·굵기·자간 | `-Display`, `-DisplayWeight`, `-Tracking` |
| 본문(body) 글꼴 | `-Body`, `-StrongWeight` |
| radius / rounded / corner | `-Radius`, `-ButtonRadius` |
| elevation / shadow / border | `-Shadow` |
| 단추 규칙(primary button) | `-Button` |
| 크기 단계(type scale), 간격(spacing), 격자 | 테마가 아니라 **페이지의 CSS** 에 쓴다 (1280 × 720 에 맞게 비율로 옮긴다) |
| 하지 말 것(don'ts), 말투 | 페이지를 쓸 때 지킨다 |

1. `new-deck.ps1 -To <덱> -Blank N` 으로 덱을 만든다.
2. 문서의 값으로 `new-theme.ps1 -Name 이름 -To "<덱>\kit" -Bg ... -Accent ...` 를 돌리고, 미리보기 그림을 본다.
3. 받은 문서를 `<덱>\design\design.md` 로 복사해 두고, 각 페이지의 테마 줄을 `../kit/theme-이름.css` 로 바꾼다(또는 2번을 먼저 하고 `new-deck.ps1 -Theme "<theme-이름.css>"`).
4. 문서에 없는 것(예: 차트 색)은 지어내지 말고 계산된 값을 쓴다. 문서와 부딪치면 문서가 이긴다.

## 7. 그대로 가져오기

사용자 자신의 것, 사용자 회사의 것일 때만 한다.

- **HTML 레퍼런스의 CSS 를 그대로**: 그 스타일시트를 덱 폴더에 복사해 페이지에서 `<link>` 로 걸고, 같은 클래스 구조로 내용을 쓴다. 가장 똑같이 나온다.
  빌드가 엔진에 맞게 변환한다. 이때는 키트 테마가 필요 없다(키트 부품을 섞어 쓰려면 2~3장으로 테마도 만든다).
  원래 화면이 1280 × 720 보다 크게 짜여 있으면 여백과 글자 크기를 캔버스에 맞게 줄여야 한다.
- **PPT 레퍼런스의 틀을 그대로**: 그 PPT(회사 템플릿)를 바탕 덱으로 쓴다. 제목·로고·바닥글은 PowerPoint 것이 그대로 남고, HTML 은 본문 자리에만 들어간다:
  `html2ppt.ps1 -Deck "템플릿.pptx" -Job job.json` 에서 `pages[].slide` 와 `area` 를 준다(`job-file.md`). 원본 PPT 는 바뀌지 않는다.
  그 자리에 들어갈 페이지는 2~3장으로 뽑은 테마를 입히고, 사이트 머리 없이(`-NoNav`) 바탕색을 슬라이드와 같게 한다. 캔버스는 그 영역의 크기다.

## 8. 글꼴

- 레퍼런스의 글꼴이 이 PC 에 있거나 스킬의 글꼴 묶음에 있으면 그대로 쓰고 페이지에 넣는다(다른 PC 에서도 같다).
- 없으면 종류에 맞춰 바꾼다: 명조류 → `Noto Serif KR`, 그 밖 → `Pretendard`. 무엇을 바꿨는지 `design.md` 3장과 실행 결과의 `NOTE` 에 적힌다. 사용자에게 알린다.
- Georgia, Segoe UI, 맑은 고딕처럼 Windows 에 늘 있는 글꼴은 넣지 않고 이름만 적는다(PowerPoint 에서는 그대로 보이고, 다른 운영체제의 브라우저에서는 뒤의 글꼴로 보인다).
- 영문 글꼴에는 한글 글꼴이 뒤에 붙는다(`"Inter", "Pretendard"`). 한글 제목의 굵기와 자간이 영문 레퍼런스와 달라 보이면 `-DisplayWeight`, `-Tracking` 으로 맞춘다.

## 9. 가져오지 않는 것

- 로고, 사진, 그림, 아이콘 묶음, 문구. 스타일(색·글자·모양·배치의 방식)만 따른다.
- 남의 사이트의 스타일시트 파일 자체. 값을 재서 비슷하게 만든다.
- 그 회사의 공식 자료처럼 보이게 하는 것(이름, 상표). 사용자의 회사가 아니면 넣지 않는다.

## 10. 한계와 확인한 범위

- 값을 고르는 규칙은 어림이다. 그림을 보는 3장의 단계를 건너뛰지 않는다.
- 자동으로 옮기지 못하는 것: 배경의 그라데이션·사진·무늬, 움직임, 아이콘 모양, 배치(격자와 여백의 규칙). 필요하면 페이지의 CSS 로 직접 쓴다.
- PPT 는 한 도형에서 글자 두 곳(처음과 가운데)만 본다. 한 상자 안에서 글꼴이 여러 번 바뀌는 덱은 일부만 잡힌다. 제목 자리(placeholder)가 없는 덱은 가장 큰 글자를 제목으로 본다.
- 테마 파일·`design.md`·`style.json` 에는 레퍼런스의 **파일 이름만** 적힌다(폴더 경로는 적지 않는다: 이 파일들은 덱과 함께 남에게 간다). 웹 주소는 그대로 적힌다.
- 확인한 것(2026-11-20, 이 PC): 직접 만든 HTML 한 장과 PPT 한 개(4장), 그림 한 장에서 바탕·면·글자·강조색·글꼴·모서리가 맞게 나옴. 뽑은 테마로 자유 페이지 3장 덱을 만들어 숨은 쇼에서 동작(44~52fps, 최신 브라우저 그림과 98.8~99.3% 같음).
  `design.md` 만 받은 경우(6장)도 끝까지 해 봄: 지어낸 디자인 문서의 값으로 `new-theme.ps1` → 빈 페이지 2장 → 숨은 쇼에서 동작, 눌러서 값이 바뀜(99.3~99.7% 같음).
  확인 못 한 것: 실제 웹 주소, 크고 복잡한 사이트나 덱, 7장의 "그대로 가져오기"(같은 CSS 를 그대로 / PPT 템플릿을 바탕 덱으로: 각각의 기능은 전부터 있었지만 레퍼런스 흐름으로 묶어서 돌려 보지는 않았다), 다른 PC.
