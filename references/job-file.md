# job 파일 (html2ppt.ps1 -Job)

슬라이드 번호·영역을 직접 지정하거나 옵션이 여러 개일 때 쓰는 JSON 파일(UTF-8). Write 도구로 만들고 `-Job "경로\job.json"` 으로 넘긴다.
상대 경로는 **job 파일이 있는 폴더** 기준이다. 한글 경로는 그대로 쓰되 `\` 는 `\\` 로 쓴다(또는 `/`).

## 형식

```json
{
  "deck": "발표.pptx",
  "out": "발표_HTML.pptm",
  "htmlDir": "pages",
  "pages": [
    { "html": "intro.html",   "slide": 1 },
    { "html": "chart.html",   "slide": 3, "area": { "left": 0, "top": 189, "width": 960, "height": 351 } },
    { "html": "map.html",     "slide": 5, "area": { "left": "50%", "top": "20%", "width": "50%", "height": "80%" } },
    { "html": "closing.html", "slide": "new" }
  ],
  "settleMs": 1500,
  "web": true,
  "share": false,
  "testClicks": [ { "slide": 3, "x": 640, "y": 100 } ]
}
```

| 항목 | 뜻 |
|---|---|
| `deck` | 올릴 대상 PPT. 없으면 새 PPT를 만든다(이때 모든 페이지는 새 슬라이드). |
| `out` | 결과 `.pptm`. 없으면 `덱이름_HTML.pptm`(덱 옆) 또는 첫 HTML 옆. |
| `htmlDir` | `pages[].html` 과 `{{html:...}}` 표식의 상대 경로 기준 폴더. 없으면 job 파일 폴더. |
| `slideSize` | 새 PPT의 크기: `"16:9"`(기본), `"4:3"`, `"1200x675"`(pt). |
| `pages[].html` | HTML 파일. |
| `pages[].slide` | 슬라이드 번호(1부터). `"new"` 또는 생략이면 맨 뒤에 빈 슬라이드를 추가해 꽉 채운다. |
| `pages[].area` | 생략: 그 슬라이드에 `{{html:...}}` 표식 도형(또는 이전 빌드의 HTML 영역)이 있으면 그 자리, 없으면 슬라이드 전체. `"full"`: 무조건 전체. 객체: `left/top/width/height` 를 pt 숫자 또는 `"35%"`(슬라이드 대비)로. |
| `settleMs` | 정지 그림을 찍기 전 대기(ms). 시작 애니메이션이 길면 늘린다. |
| `pictureScale` | 정지 그림을 캔버스의 몇 배로 그릴지(1~4, 기본 2). 4K 화면에서 매크로 없이 볼 때도 또렷해야 하면 3. 파일은 커진다. |
| `shotWidth` | 쇼 실측 그림의 폭(기본 1600 으로 줄임). 원본 해상도로 선명도를 확인하려면 `8000`. |
| `web` / `share` | 웹 버전 `.html` / 공유 폴더+zip 도 만든다(명령의 `-Web` / `-Share` 와 같다). 웹 버전은 만든 뒤 Edge로 열어 확인한다(`web_slide_NN.png`). |
| `engine` | 쇼에서 페이지를 돌릴 엔진. `"auto"`(기본: 최신 엔진용으로 쓴 그대로 넣고, 되는 장은 기존 엔진용 사본도 넣는다) · `"modern"`(최신 엔진용만, 빌드가 빠르다) · `"classic"`(기존 엔진용만, v2 방식). 명령의 `-Engine` 과 같다. `references/modern-web.md` 7장. |
| `testFallback` | `true` 면 쇼 시험을 기존 엔진으로 한 번 더 돌린다(`engine` 이 `auto` 일 때). 명령의 `-TestFallback`. 그림은 `shots_classic\` 에 따로 남는다. |
| `convert` | 기존 엔진용 사본을 만들 때의 변환: `"auto"`(기본: 최신 문법을 쓰는 페이지만 자동 변환) · `"always"` · `"never"`. 명령의 `-Convert` 와 같다. |
| `fonts` | `"auto"`(기본: 페이지가 쓰는 글꼴을 페이지 안에 넣는다) · `"off"`. 명령의 `-Fonts` 와 같다. |
| `images` | `"auto"`(기본: 300KB 넘는 그림을 캔버스의 3배까지 줄이고, PNG로 저장된 사진은 JPEG로, 누운 사진은 바로 세운다) · `"keep"`. 명령의 `-Images` 와 같다. |
| `testClicks` | 쇼 실측 때 해당 슬라이드의 HTML을 실제로 눌러 본다(누르기, 길게 누르기, 끌기, 글자 넣기, 값 읽기). 아래 "클릭 시험" 참고. |

## 클릭 시험 (`testClicks`)

불러올 때는 멀쩡하지만 누르면 오류가 나는 페이지를 잡는 방법이다. 쇼 시험은 장마다 **얼마나 부드러운지도 잰다**:
`60 fps while appearing (longest frame 17 ms)` 는 그 장이 나타나는 1.7초 동안의 초당 프레임과 가장 길었던 한 프레임,
`... fps during the test actions` 는 아래 동작을 하는 동안의 값이다(이 PC 실측: 최신 엔진 60, 기존 엔진 33~54. 30 아래면 경고).

최신 엔진에서는 동작을 브라우저의 입력 통로(개발자 프로토콜)로 넣는다. 진짜 입력과 같아서 포인터가 지나간 곳의 hover, 입력창의 글자, 키가 그대로 페이지에 닿는다.
기존 엔진에서는 그 창에 Windows 메시지를 보내는 방식이라 닿지 않는 키가 있고 휠은 쓸 수 없다.

| 동작 | 쓰는 법 |
|---|---|
| 누르기 | `{ "slide": 3, "x": 640, "y": 100 }` |
| 길게 누르기 | `{ "slide": 3, "x": 1174, "y": 38, "hold": 800 }` (ms 동안 누르고 있다가 뗀다) |
| 끌기 | `{ "slide": 3, "x": 205, "y": 321, "to": [380, 321] }` (`hold` 를 함께 주면 그만큼 누르고 있다가 끈다) |
| 글자 넣기 | `{ "slide": 3, "text": "ABC" }` (앞의 누르기로 글자 넣을 곳을 정한 뒤. 입력창과 `contenteditable` 모두) |
| 휠 | `{ "slide": 2, "x": 640, "y": 360, "wheel": 760 }` (그 자리에서 760px 만큼 아래로. 음수는 위로. 최신 엔진만) |
| 키 | `{ "slide": 3, "key": 13 }` (가상 키 코드. 기존 엔진의 숨은 쇼에서는 페이지에 닿지 않는 키가 있다) |
| 값 읽기 | `{ "slide": 3, "eval": "document.getElementById('n').textContent" }` (그 페이지 안에서 계산한 값이 보고에 `eval: 식 => 값` 으로 나온다) |

- 어느 동작에나 `"wait": ms` 를 붙여 그 뒤에 쉬는 시간을 바꾼다(기본 900).
- `eval` 은 누를 자리를 찾는 데도 쓴다: `"var r = document.querySelector('.ph-chip').getBoundingClientRect(); Math.round(r.left + r.width / 2) + ',' + Math.round(r.top + r.height / 2)"`.
  키트의 도구를 직접 부를 수도 있다(`"PH.edit.on(); 'on'"`). 시험 중에 페이지가 보관한 것(고친 글자, 투표)은 **파일에 저장되지 않는다**(시험은 읽기 전용으로 연다).
- 좌표는 **그 페이지의 창 안 CSS px**(보이는 화면의 왼쪽 위가 0,0)이다. 슬라이드 좌표가 아니다. 스크롤한 페이지에서도 지금 보이는 화면 기준이다.
- 좌표는 정지 그림 `page_NN.png` 에서 읽는다. 그 그림은 캔버스의 2배 크기이므로 **그림 좌표 ÷ 2**. (CSS에 적은 left/top 값으로 계산해도 된다.)
  Read 도구가 그림을 줄여서 보여 줄 때는 줄어든 비율도 곱한다(예: 2560 폭 그림이 2000 폭으로 보이면 보이는 좌표 × 1.28 ÷ 2).
- 같은 슬라이드에 여러 항목을 주면 적힌 순서대로 하고(상태가 쌓인다), 마지막 동작 뒤에 한 번 찍는다.
- 결과는 `show_slide_NN.png` (동작 **뒤**의 쇼 화면)이고 보고에 `picture taken after N test action(s)` 로 표시된다. 누르기 **전** 모습은 `page_NN.png` 이니 둘을 비교한다.
  다른 장으로 넘어가는 동작(목차 카드, 슬라이드 고르기)을 하면 그 그림에는 넘어간 장이 찍힌다.
- 동작 뒤 스크립트 오류가 나면 그 슬라이드 줄에 `script errors:` 로 나온다.

## 규칙

- `pages` 에 없는 슬라이드라도 `{{html:파일}}` 표식이 있으면 자동으로 포함된다(파일은 `htmlDir` 기준).
- 슬라이드 한 장에 페이지 하나. 같은 슬라이드를 두 번 지정하면 오류.
- 웹 버전의 이름은 `.pptm` 과 같은 이름의 `.html` 이다. 같은 이름의 페이지 원본이 그 자리에 있으면 덮어쓰지 않고 `이름_web.html` 로 쓴다.
- 영역을 주면 그 자리의 표식 도형/이전 정지 그림은 새 정지 그림으로 바뀐다(겹침 순서 유지).
- 영역의 pt 는 PowerPoint의 위치·크기 값과 같다(16:9 기본 슬라이드는 960×540pt). **캔버스(px) = 영역(pt) × 4/3.**

## 예

기존 덱의 2·4번 슬라이드 아래쪽 65%에 올리고 공유 묶음까지:

```json
{
  "deck": "C:\\작업\\분기보고.pptx",
  "pages": [
    { "html": "C:\\작업\\html\\kpi.html",   "slide": 2, "area": { "left": 0, "top": "35%", "width": "100%", "height": "65%" } },
    { "html": "C:\\작업\\html\\trend.html", "slide": 4, "area": { "left": 0, "top": "35%", "width": "100%", "height": "65%" } }
  ],
  "share": true
}
```

이미 이 스킬로 만든 `.pptm` 의 페이지를 고쳐 다시 올릴 때: `deck` 에 그 `.pptm` 을 주고 `pages` 에 바꿀 슬라이드와 새 HTML을 준다.
영역을 생략하면 이전 자리를 그대로 쓴다. **`pages` 에 넣지 않은 이전 HTML 슬라이드는 정지 그림만 남는다**(보고에 경고가 나온다) — 계속 쓰려면 전부 다시 적는다.
