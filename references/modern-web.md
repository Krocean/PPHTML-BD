# 요즘 웹 그대로 쓰기 (최신 엔진)

v3부터 슬라이드 쇼 안의 페이지는 **Microsoft Edge 의 엔진(WebView2)** 으로 돈다. 그래서 페이지는 "PPT용 HTML"이 아니라 **그냥 웹 페이지**다.
요즘 브라우저에서 되는 것은 쇼 안에서도 된다. 변환도, 옛 엔진 규칙 검사도 거치지 않는다.
여기 적힌 것은 화면에 보이지 않는 실제 슬라이드 쇼에서 확인한 것이다(2026-11-20, Windows 11, PowerPoint LTSC 2024, Edge 157). 확인하지 못한 것은 맨 끝에 적었다.

## 목차
1. 엔진이 둘이다
2. 페이지를 쓸 때 아는 것 셋 (창 크기, 파일 하나, 슬라이드 쇼와의 약속)
3. 슬라이드 쇼와 이어지는 것 (`pptHtml`, 이벤트, 키와 휠)
4. 움직임과 소리
5. 한 파일로 들어간다는 것 (라이브러리, 모듈, 자료)
6. 발표 도구를 자유 페이지에 쓰기
7. 대비용 기존 엔진
8. 쇼 시험으로 눌러 보기
9. 써 볼 만한 것들 (예시 덱의 어느 장에 있는지)
10. 남는 제약, 확인한 것과 못 한 것

## 1. 엔진이 둘이다

| | 최신 엔진 (기본) | 기존 엔진 (대비용) |
|---|---|---|
| 무엇 | Edge WebView2 (Chromium) | Internet Explorer 11 브라우저 컨트롤 |
| 페이지 | 쓴 그대로 | 자동 변환한 사본 (안 되는 페이지는 사본이 없다) |
| 움직임 | 실측 초당 60프레임 | 실측 33~54프레임, 큰 것은 움직이지 않게 써야 함 |
| 어디에 있나 | Windows 11 기본, 요즘 Windows 10·Office·Edge 에 포함 | 모든 Windows |
| 언제 쓰이나 | 그 PC 에 WebView2 가 있으면 항상 | WebView2 가 없거나 뜨지 않을 때 스스로 |

발표 파일(`.pptm`) 안에는 장마다 두 벌이 들어간다: 쓴 그대로의 페이지와, 기존 엔진용 사본(만들 수 있을 때만). 쇼가 시작될 때 호스트가 최신 엔진을 먼저 띄워 보고, 안 되면 기존 엔진으로, 그것도 안 되면 정지 그림으로 남는다.
**그러니 페이지는 최신 엔진만 생각하고 쓴다.** 기존 엔진에서도 돌아야 하는 자료(오래된 PC 가 많은 곳에 보낼 때)만 7장을 본다.

## 2. 페이지를 쓸 때 아는 것 셋

**창 크기.** 페이지는 항상 같은 크기의 브라우저 창으로 보인다: 영역의 pt × 4/3 CSS px. 16:9 슬라이드 전체면 **1280 × 720**.
발표 화면이 노트북이든 4K 든 그 크기의 창이 화면에 맞게 확대될 뿐이다(글자·선은 또렷하다). 반응형으로 쓸 필요는 없고, 그 창에서 보기 좋으면 된다.
`vw` `vh` `clamp()` 미디어 쿼리·컨테이너 쿼리는 모두 그 창을 기준으로 동작한다.

**길이는 자유.** 한 화면(720px)에 맞춰도 되고, 더 길게 써서 **슬라이드 안에서 스크롤**하게 해도 된다(휠, 터치, Space, PageDown). 슬라이드의 정지 그림은 맨 위 화면이다.

**파일 하나.** 빌드가 페이지가 쓰는 로컬 파일(CSS, JS, 그림, 글꼴)을 페이지 안으로 넣는다. 서버가 없으므로 페이지 밖의 파일을 실행 중에 읽어 오지는 못한다(5장).

출발점: `new-deck.ps1 -Blank N` 이 만드는 빈 페이지(`assets/page-blank.html`). `<html class="ph-free">` 는 키트의 고정 틀을 끄는 표시다. 그 파일의 `<style>` 과 `<body>` 는 통째로 바꿔도 된다. 키트를 아예 쓰지 않는 페이지도 된다(키트 줄을 지운다).

## 3. 슬라이드 쇼와 이어지는 것

빌드가 모든 페이지에 넣어 주는 것(키트와 상관없이 항상 있다):

```js
pptHtml.next(); pptHtml.prev(); pptHtml.gotoSlide(3);   // 슬라이드 넘기기 (다음 단계의 애니메이션도 PowerPoint 가 한다)
window.addEventListener("pptshow", fn);                 // 이 장이 화면에 나올 때마다 (처음 포함)
window.addEventListener("ppthide", fn);                 // 화면에서 나갈 때
pptHtml.saveState(text); pptHtml.loadState();           // 발표 자료 안에 남길 글자(고친 내용, 고른 값). 저장하면 파일에 남는다
pptHtml.engine;                                         // "modern" | (기존 엔진에서는 없음)
pptHtml.host;                                           // "powerpoint" | "web"(웹 버전) | "preview"(빌드 중)
pptHtml.deck;                                           // { n, total, slides: [{ n, title, thumb }] }
pptHtml.keepKeys = true;                                // 아래의 키·휠 전달을 끈다(게임, 단축키가 많은 화면)
```
옛 방식(`window.pptHtmlOnShow = function () {}` / `pptHtmlOnHide`)도 그대로 불린다.

**키.** 페이지에 포커스가 있을 때:
- `←` `→` `Esc` 는 슬라이드 쇼로 간다(넘기기, 끝내기).
- `Space` `PageDown` `PageUp` `↑` `↓` `Home` `End` 는 **스크롤할 것이 있으면 페이지가 쓰고**, 없으면 슬라이드 쇼로 간다.
- 입력창·`contenteditable` 안에서는 아무것도 가로채지 않는다(`Esc` 는 입력에서 빠져나온다). 단추 위의 `Space` 는 단추를 누른다.
- 페이지가 `preventDefault()` 한 키는 건드리지 않는다. 그 밖의 글자 키는 전부 페이지 것이다(단축키를 만들어도 된다).
- 브라우저 자신의 단축키(F5, Ctrl+R/P/F, Ctrl+확대, Alt+←)는 꺼 두었다. 오른쪽 단추 메뉴도 없다(직접 `contextmenu` 를 만들 수는 있다).

**휠.** 스크롤할 것이 있으면 스크롤, 없으면 보통의 슬라이드 쇼처럼 다음/이전 슬라이드. 페이지가 휠을 직접 쓰면(`preventDefault()`) 건드리지 않는다.

**입력.** `<input>` `<textarea>` `<select>` `contenteditable`, 끌기(pointer events), `<dialog>`, `popover` 가 그대로 된다.

## 4. 움직임과 소리

- CSS 애니메이션·전환, Web Animations, `requestAnimationFrame`, 캔버스, WebGL 모두 제한 없이 쓴다. "큰 것은 움직이지 않는다"는 규칙은 **기존 엔진의 것**이다(실측: 전체 화면 캔버스 + 흐림 + 혼합 모드를 겹쳐도 60프레임).
- 다음 장의 페이지는 **미리 불러 둔다**(넘기는 순간 바로 보이게). 그래서 처음 들어올 때의 CSS 애니메이션이 화면에 나오기 전에 끝나 버리지 않도록, 페이지는 **처음 화면에 나올 때까지 CSS 애니메이션을 멈추고 있다가** 나오는 순간 시작한다. 따로 할 일은 없다.
- 그 장으로 **다시 돌아왔을 때** 또 움직이게 하려면 `pptshow` 에서 직접 한다(숫자 다시 세기, 클래스 뗐다 붙이기, 스크롤 맨 위로).
- 화면 밖의 페이지는 그리지 않는다(`requestAnimationFrame` 이 쉰다). 타이머는 느리게 돈다. 화면에서 나가면 재생 중인 `<video>` `<audio>` 는 멈추고 돌아오면 이어진다.
- 소리와 동영상이 누르지 않아도 재생을 시작할 수 있도록 엔진을 띄운다(발표에서는 그것이 자연스럽다). 재생 자체는 아직 확인하지 못했다.

## 5. 한 파일로 들어간다는 것

| 쓰려는 것 | 방법 |
|---|---|
| 내 CSS / JS 파일, 그림, 글꼴 | 상대 경로로 걸면 빌드가 페이지 안으로 넣는다. 글꼴은 쓰인 글자만 잘라 넣는다 |
| 라이브러리 (GSAP, D3, Three.js, Chart.js …) | 그 파일을 덱 폴더에 두고 `<script src="lib/…">` 로. 인터넷 주소(CDN)로 걸면 되기는 하지만 발표장에 인터넷이 없으면 안 열린다(보고에 `warn needs internet`) |
| ES 모듈 | 한 페이지 안의 `<script type="module">` 은 된다. 다른 파일을 `import` 하는 모듈은 먼저 한 파일로 묶는다(번들) |
| React / Vue / Svelte 로 만든 화면 | 빌드 결과가 한 HTML + 스크립트 한두 개면 그대로 된다. 여러 조각을 실행 중에 불러오는 빌드(코드 스플리팅)는 한 파일로 나오게 설정한다 |
| 자료 (JSON, CSV) | 페이지 안에 적는다(`<script type="application/json">` 이나 변수). 실행 중에 로컬 파일을 `fetch` 하지 못한다 |
| 큰 동영상 | 페이지에 넣으면 발표 파일이 그만큼 커진다. 짧게 줄이거나 인터넷 주소로 건다 |

페이지는 `https://ppt-html.example/…` 이라는 자기만의 주소로 열린다(이 PC 안에서만 통하는 이름). 그래서 보안 컨텍스트가 필요한 기능도 쓸 수 있고, 같은 덱의 페이지들은 `localStorage` 를 함께 쓴다.
단 `localStorage` 는 **그 PC 에만** 남는다. 파일과 함께 가야 하는 값은 `pptHtml.saveState` 로 남긴다.

## 6. 발표 도구를 자유 페이지에 쓰기

`kit.js` + `kit-deck.js` 를 걸고 `PH.deck()` 을 부르면(빈 페이지는 이미 그렇게 되어 있다) 어떤 페이지에서도 발표 도구가 된다:
오른쪽 아래 구석에서 나오는 도구 막대(평소엔 숨김), 쪽 번호를 길게 눌러 장 고르기, 연필(글자 고치기·옮기기·크기), 펜. 고친 내용은 쇼가 끝날 때 슬라이드 그림에도 반영된다.
- 고칠 수 있는 것은 글자가 직접 든 요소다. 스크립트가 다시 그리는 글자는 다시 그릴 때 원래대로 돌아가므로, 고쳐도 되는 글자는 HTML 에 적는다.
- 스크롤하는 페이지에서도 도구는 화면에 붙어 있다(`ph-free`).
- 도구가 필요 없으면 세 줄(스크립트 둘, `PH.deck()`)을 지운다. 키트의 부품(`ph-card`, `PH.bars` …)은 쓰고 싶을 때만 쓴다(`kit.md`).

## 7. 대비용 기존 엔진

`html2ppt.ps1 -Engine` (job 파일 `"engine"`):

| 값 | 하는 일 |
|---|---|
| `auto` (기본) | 최신 엔진용으로 만들고, 같은 페이지를 기존 엔진용으로도 자동 변환해 본다. 되면 사본이 들어가고(`fallback ready`), 안 되면 그 장은 대비 없이 간다(`no fallback`). **빌드를 막지 않는다** |
| `modern` | 최신 엔진용만. 빌드가 빠르다. WebView2 가 없는 PC 에서는 정지 그림 |
| `classic` | 기존 엔진용만(v2 방식). 변환·검사가 빌드를 막을 수 있다 |

- 유리 효과, `:has()`, 스크롤 연동 애니메이션, View Transitions, `<dialog>` 같은 것을 쓴 페이지는 기존 엔진용 사본이 만들어지지 않는다. 그것이 정상이다.
- 기존 엔진에서도 꼭 살아 있어야 하는 장이면: 그 장을 flex·간단한 grid·ES5 수준으로 쓰거나 키트 부품으로 쓴다(`kit.md`, `ie11-rules.md`). 빌드 보고의 `fallback ready … NN% like the modern one` 과 비교 그림을 본다.
- `-TestFallback` 을 붙이면 쇼 시험을 기존 엔진으로 한 번 더 돌린다.
- 파일의 프레젠테이션 꼬리표 `HtmlEngine = classic` 은 그 파일의 쇼를 기존 엔진으로 돌리게 한다(문제 추적용).

## 8. 쇼 시험으로 눌러 보기

job 파일의 `testClicks` 에 적으면 숨은 슬라이드 쇼에서 실제로 해 본다. 좌표는 페이지의 CSS px(1280 × 720 창 기준).
최신 엔진에서는 브라우저의 입력 통로로 넣으므로 진짜 입력과 같다(hover, 포인터 이동, 입력창의 글자).

```json
{ "slide": 2, "x": 640, "y": 360, "wheel": 760 }          // 휠을 760px 만큼 아래로
{ "slide": 4, "x": 1030, "y": 408 }, { "slide": 4, "text": "김하늘" }   // 입력창을 누르고 글자 넣기
{ "slide": 3, "x": 612, "y": 536, "wait": 900 }           // 누르고 0.9초 기다림(전환이 끝나도록)
{ "slide": 1, "x": 700, "y": 200, "to": [1000, 420] }     // 끌기
{ "slide": 4, "eval": "document.getElementById('done').open" }   // 값 읽기(보고에 나온다)
```
요소의 자리를 모르면 먼저 `eval` 로 `getBoundingClientRect()` 를 읽어 보고 좌표를 정한다. 보고에는 장마다 초당 프레임과 가장 긴 프레임이 나온다.

## 9. 써 볼 만한 것들

예시 덱 "별마루 천문대"(지어낸 내용, `ppt-html_예시덱\7_최신웹_천문대`)에서 실제로 돌려 본 것:

| 기법 | 어디에 | 한 줄 |
|---|---|---|
| 캔버스 별하늘 + 마우스 시차 | 1장 | `requestAnimationFrame`, 화면에서 나가면 쉰다(`ppthide`) |
| 움직이는 오로라 | 1장 | `@property` 로 각도를 움직이는 `conic-gradient` + `filter: blur` + `mix-blend-mode` |
| 유리 카드, 3D 기울임, 자석 단추 | 1장 | `backdrop-filter`, `perspective` + `rotateX/Y`, `translate` |
| 슬라이드 안에서 스크롤하는 이야기 | 2장 | `animation-timeline: scroll()` / `view()`, `position: sticky`, `scroll-snap`, `IntersectionObserver` |
| 화면 전환 | 3장 | `document.startViewTransition()`: 고리가 다음 별로 미끄러져 간다(`view-transition-name`) |
| SVG 지도 + 선이 그려지는 효과 | 3장 | `stroke-dashoffset` 전환, `:has(#lines:checked)` 스위치 |
| 컨테이너 쿼리 | 3장 | 카드 폭에 따라 숫자 칸 수가 바뀐다 |
| 진짜 입력 양식 | 4장 | 라디오 카드 `:has(:checked)`, `<input>` 글자 입력, `<output>`, `popover` + 앵커 위치, `<dialog>` + `::backdrop` 흐림 |
| 보관 | 4장 | 고른 날짜·인원·이름이 `pptHtml.saveState` 로 파일에 남는다 |

그 밖에 요즘 화면에서 흔한 것: 벤토 격자, 큰 글자와 `text-wrap: balance`, 가변 글꼴, `oklch` 와 `color-mix()`, 중첩 CSS, 커서 따라다니는 빛, 숫자 굴리기, 드래그로 순서 바꾸기, 명령 팔레트, 탭과 아코디언, 마키, WebGL 셰이더 배경. 전부 그냥 쓰면 된다.
디자인을 어디서 가져올지는 `design-from-reference.md`, 문장과 순서는 `storytelling.md`.

## 10. 남는 제약, 확인한 것과 못 한 것

남는 제약(엔진이 아니라 "PowerPoint 안"이라서 생기는 것):
- 슬라이드 한 장에 페이지 하나, 창 크기는 고정(확대만 된다). 페이지가 새 창을 열거나 파일을 내려받게 하지는 않는다.
- Windows 용 PowerPoint 데스크톱 + 매크로 허용이 필요하다. 매크로가 꺼진 PC·Mac·웹 PowerPoint 에서는 정지 그림이고, 그런 곳에는 웹 버전(`.html`)을 준다(웹 버전도 쓴 그대로의 페이지를 쓴다).
- WebView2 가 없는 PC 에서는 대비용 사본이 있는 장만 살아 있다.
- 동시에 살아 있는 페이지는 10장까지다(장마다 브라우저 프로세스). 그보다 긴 덱에서는 오래 안 본 장부터 내려가고, 돌아오면 다시 불러온다(보관한 값은 그대로, 그 밖의 화면 상태는 처음으로).
- 발표자 도구(두 화면)에서는 청중 화면에만 페이지가 뜬다. 슬라이드 전환 효과 중에는 페이지가 바로 나타난다.

확인한 것(숨은 슬라이드 쇼, 이 PC): 최신 엔진으로 예시 덱 네 장(9장의 표에 적은 기법 전부)과 키트로 쓴 장 셋이 살아 있고 초당 60프레임(가장 긴 프레임 17~50ms). 휠 스크롤, 누르기, 끌기, 입력창 글자 입력, `<dialog>`, View Transitions, 스크롤 연동 애니메이션, 유리 효과.
발표 도구(구석에서 나오는 막대, 글자 고치기, 저장 뒤 다시 열어도 유지, 쇼 뒤 슬라이드 그림 갱신). 처음 장이 살아나기까지 쇼 시작 뒤 0.7초쯤, 다음 장은 미리 불러 둠. 기존 엔진으로 강제했을 때의 대비 동작.

확인 못 한 것: 실제 모니터에서 사람이 누르는 것(시험 입력은 브라우저의 입력 통로로 넣었다), 한글 입력기 조합(완성된 글자를 넣는 것만 확인), 터치, 소리·동영상 재생, WebGL, 카메라·마이크 같은 권한이 필요한 기능, 인터넷 주소의 자원, 10장이 넘는 덱의 내려갔다 올라오기, 발표자 도구 두 화면, 배율이 다른 두 모니터, WebView2 가 없는 PC·다른 Office 버전·보안 정책이 다른 PC(그런 곳에서는 대비 동작으로 내려가도록 만들었지만 그 PC 에서 돌려 보지는 못했다).
